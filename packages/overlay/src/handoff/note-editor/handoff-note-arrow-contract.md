# Handoff note arrow navigation contract

Collapsed caret only. Doc/wire line = segment between `\n` characters (not visual wrap).

## Shift+Enter (soft line break)

Editor-owned (`beforeInput` → `applyDocLineBreak`); browser default is prevented.

Follows the **default soft line-break contract** used by typical text fields and chat editors (Slack, Discord, Notion, etc.):

- Insert `\n` at the caret (or before an atomic `@` pill when the caret is on the pill start).
- **Caret lands on the new blank at or after the break** — on the inserted line, ready to type.
- **Caret never regresses** to an earlier wire offset on the same break (no backward jump to the previous visual row’s content end).
- Consecutive Shift+Enter presses advance monotonically through blank lines (no freeze).
- **EOF trailing blank band:** when a break extends a blank run at doc end with no substantive row below, caret lands on the **new blank’s probe wire** (last probe in that band), not past `wire.length`. The next insert fills that visual row; backspace on that blank uses blank-band collapse.
- **Wire newline line box:** wire `\n` renders as `<br data-handoff-wire-break>`; when the document ends with `\n`, an extra `<br data-handoff-line-pad>` (layout-only, not wire) creates a paintable blank line and caret target after the first break.

Mention-boundary breaks (caret on pill start) use the same caret rule: newline before the pill, caret on that new blank — same as whitespace-only inter-pill gaps.

## Up / Down — vertical only

- **One keypress = one visual row** (what the user sees), whether the row comes from soft wrap, a wire `\n` line, or a Shift+Enter break.
- **Vertical goal column** (measured X) sticks across consecutive Up/Down on **content rows** until a horizontal arrow, **click ingress** (user reposition), or doc mutation. Crossing into or through an **embedded blank band** follows the blank rules below (goal resets to visual row start).
- **Content rows — preserve column:** when the target row has substantive content, land at the sticky goal column by resolving the visual point on the target row first (DOM pill half-split when sticky X is inside a painted pill bbox; else DOM point probe when an editor root is available; sparse samples only as fallback); **clamp** if the row is shorter. **Shorter target row — content end:** if sticky goal X is past the target row’s content extent, land at that row’s **content end** (last valid caret on the row — text tail or pill end per mention atomicity). Do not land in trailing empty layout past content. **Sticky after clamp (layout authority):** preserve the pre-clamp goal when the target is a **post-mention soft-wrap continuation row**, or when moving **Up** into a shorter row separated from the source row by **same-wire soft wrap only** (no embedded `\n` between row wire ranges — classic column stickiness). Mid-text soft wrap needs the probe because boundary samples omit interior columns.
- **Content rows — row start:** when sticky goal is at the visual row’s left edge, land at that same edge on the target content row — not the previous row’s end, not max-wire tail, not wire-column preservation across rows.
- **Wire `\n` segments** are storage only — they do not choose the step. They matter for **landing** (which doc offset matches the target visual row + goal column).
- **Mention atomicity:** never land inside a pill. When sticky goal X is strictly inside a pill’s painted horizontal span (DOM bbox on probe, layout sample span on sparse fallback), land at **pill start** when X is in the left half of that span and **pill end** when X is in the right half — same rule for Up and Down, including two pills on one row. If past the pill → text at that column.
- **Vertical landing owner (overlay):** after layout/DOM probe picks target wire, land via `resolvePaintContextAtWire(...).paintPos` (then normalize with `from`). DOM column probe returns paint pos directly (no wire round-trip through a layout paint-index).
- **up/down from content:** enter the first visual row below (including empty rows); do not jump to a later mention on the current row.
- **Boundary bleed (Clash-style):** when **no visual row** remains above/below, vertical key **falls through to horizontal** on the current row — not a no-op.
  - **First visual row + Up** → same as **Left** (one horizontal step back).
  - **Last visual row + Down** → same as **Right** (one horizontal step forward).
  - **Multiline `\n` docs:** bleed only at the true visual top/bottom once layout is exhausted.
- **Mid-document:** Up/Down never substitute horizontal motion; only at visual extremes.
- **Editor resolution order (overlay):** (1) **visual row** when layout has another row above/below — land per column rules (content preserve vs blank row start), using the source caret's DOM rect for the goal X when available; (2) **boundary bleed** only at true visual top/bottom once layout is exhausted; (3) otherwise **no-op** (`handled: false`). Overlay does not wire-cross; core `resolveDocVerticalArrowMove` is doc-policy only. **`resolveDomVerticalArrowMove`** is the production path (DOM geometry first). Measured-only test helpers may exercise sparse **row-edge** fallback (row start/end, past-end); interior column preservation without a DOM probe is not the UX contract.
- **Unsampled wire offsets:** sparse layout samples bracket each wire offset to a visual row (interpolate Y between bracketing samples, or measure text-node coords when the editor root is available). **Column on content rows:** DOM pill half-split when sticky X is inside a painted pill bbox; else DOM point probe on the target row at the layout map’s target-row Y and sticky goal X. After a probe miss, sparse fallback is **edge-only** — row visual start, row content end (including source-at-row-end → target row end), and past-end snap to the nearest layout sample on the target row. **Source-at-row-end** is detected when the caret wire is at doc-order row tail and sticky goal X matches that wire's measured column — not via row-tail wire pick (which can alias promoted mention-end samples). **No interior column interpolation** between sparse samples; mid-row column preservation requires a successful DOM probe. Mention half-split still applies on sparse edge landings when goal X is inside a pill sample span. **Same-wire soft-wrap band:** adjacent content rows with no `\n` in `[upperRowMaxWire, lowerRowMinWire)` — the upper row max sample may sit on the wire `\n`; that counts as a wire-line break, not soft wrap. **Past-end** snap: when the source is at doc past-end or sparse row-end landing targets an unsampled wire, snap to the nearest layout sample on the target row. Mention atomicity applies on edge landings (goal inside pill span → boundary, not interior).
- **Post-mention soft-wrap tail:** when substantive text after a mention wraps entirely to the next visual row (row-0 spacer prefix only, lower-row tail anchor sample), layout promotes continuation samples and assigns unsampled interior wires to the wrap row — not the pill band via mention-adjacent align. **Column:** wrap-tail coords bracket within the continuation fragment (wrap-row `left`), not row-0 tail samples at mention-band X. **Not cross-row inter-atomic spacer:** a whitespace-only pre-atomic gap node painted above its following atom (different measured rows) uses paint authority (`layoutRowForFocus`, `crossRowInterAtomicSpacers` infer set) — not post-mention soft-wrap continuation promotion.
- **Wire-newline row visual start (layout):** when substantive text begins after an embedded `\n` (normal line break, not a blank band), layout may promote a sample at that segment’s **first substantive wire** so blank-band exit and row assignment see the painted line start. That sample’s **`left` is the visual start of the line** — wire-break geometry or measured text coords — **never** the past-end / EOF column of a longer row. Past-end samples keep wide sticky column; line-start samples keep row-start geometry. Do not copy max-row `left` onto the first character.
- **Embedded blank bands (Shift+Enter empty rows):** stacked empty **visual** rows between substantive content — from Shift+Enter in a text node (with or without a preceding mention). **Visual row is the authority for Up/Down:** one keypress moves to the adjacent painted row above or below. Wire may contain multiple `\n` characters; they are **storage only** — navigation does **not** allocate one arrow row per `\n` by default.
  - **Line break vs blank line:** `\n` means “move to a new line,” not “insert a blank line.” What the user sees depends on what comes before and after the break. If substantive text follows, it is a normal line break (`a\nb` → two lines: `a`, then `b`). A blank line appears only when an **empty segment** sits between line breaks — nothing between two `\n` (`a\n\nb` → three lines: `a`, blank, `b`). The blank is the empty segment, not the `\n` character itself.
  - **What counts as one blank visual row:** an empty line the user sees between substantive lines (e.g. `header` → empty line → `tail` is **three** visual rows). Consecutive Shift+Enter presses that add empty lines each advance the caret through those rows monotonically (Shift+Enter section above).
  - **What is not an extra blank row:** a `\n` that only **starts** the next substantive line on the row below (e.g. the second `\n` in `header\n\ntail` before `tail`) is line-start storage for the tail row — **not** a second empty row to step through. Do not treat “line break before next content” as a blank-band stop.
  - **Blank-band column (standard empty-line behavior):** an empty visual row has no interior column — landing is always at that row’s **visual line start** (break wire from layout / `<br data-handoff-wire-break>` geometry). **Entering a blank row resets sticky goal column to that visual start.** Blank → blank stays at visual start. Blank → content lands at the target content row’s **visual start** (row-start rule) — do not carry a prior content row’s end column through the band.
  - **Examples:** `header\n\ntail` — three visual rows (header, blank, tail). From end of `tail` at visual start: **Up** → blank at visual start; **Up** → header at visual start. From end of `tail` at a later column (e.g. pill end): **Up** → nearest blank at visual start (sticky resets); further **Up** through blanks at visual start; **Up** to header at visual start — not at the pre-band pill-end column. Not four rows; not a stop on the `\n` before `tail` unless that row is visually empty.
  - **Layout:** content rows and blank rows are ordered by measured **`top`** (visual Y). Mention end and immediately following text on the same paint band share one visual row before clustering. **Down from content:** skip inline blanks that share the current row’s measured top (first break on the same paint band). **Up** steps through each **visual** row above, not each wire `\n`. Row clustering merges pill midYs with measured sample tops for soft wrap. Horizontal bleed must not substitute when another visual row exists.
  - **Core helper:** `listEmbeddedBlankBandProbeWires` identifies break wires for **empty** visual rows only (`next` segment length 0) — not whitespace-only content rows, not substantive wire-line breaks like `line1\nline2`, and not a content line-start `\n` before the next populated segment.

### Wire `\n` classification for layout (extends §36–38)

On the wire, `\n` always means **start next line**. Layout and navigation classify the **segment after** that break:

- **Empty segment after `\n`** (length 0 until the next break) → **blank visual row**. Each empty line the user sees is one Up/Down step. Layout must **not collapse** consecutive empty rows into one row.
- **Whitespace-only or substantive text after `\n`** → **content visual row** (normal line break). Typed spaces graduate the row out of blank-band probe ownership — click/Delete/Backspace treat those spaces as characters (industry norm). Example: `line1\nline2` — row for `line1`, then row for `line2`. Layout must assign a **distinct measured top** per content wire line inside embedded text nodes, not fold the whole node into one visual row.

Stacked Shift+Enter blanks (`\n\n` with empty segments) remain **separate blank visual rows** — Up/Down round-trip parity through each blank row.

## Click ingress (text mousedown / selectionchange)

Editor-owned reconciliation on `selectionchange` after user click. Builds on pill-click (§ Pill click selection); does **not** change Backspace/Delete at blank-band probes policy.

### Paint authority (row / caretKind / DOM)

When the same wire offset aliases multiple doc owners (mention-start vs cross-row inter-atomic spacer tail, probe vs content-row end), **paint, layout row, and caretKind follow focus doc position → paint doc position → measured geometry** — not raw wire alone.

- **`resolvePaintContext(doc, focus, { root?, from? })`:** canonical overlay paint authority — `{ focusPos, paintPos, caretKind }`. Doc-primary entry for paint seams; wire import uses `resolvePaintContextAtWire`. Thin aliases (`resolvePaintDocPos`, `describeCaretContext`, `docPosAtPaintWire`) delegate here. **`caretKind` from paint doc pos** (text node → `text`); wire lookup only when paint pos is on a mention node.
- **Focus disambiguation at alias wires:** when the same wire aliases multiple doc owners, `focusPos` is resolved structurally — **incoming/from authority wins** when `docPosToWireOffset(incoming/from) === wire` (editor selection, click repair, DOM read-back). Otherwise canonical owner at wire: `mention-boundary` end → post-atomic text offset 0 when preceded by atomic node; `mention-boundary` start → inter-atomic-gap text tail when pattern is `atomic | text | atomic` on same wire, else atomic offset 0; `mention-interior` → core interior landing; `text` → first text owner at wire in doc order.
- **Cross-row inter-atomic spacer:** atomic start at a wire shared with a spacer text tail maps to the spacer tail **only** when spacer and following atom are on **different visual rows** (midY gap > 4px). Adjacent atoms on the same row keep separate paint owners.
- **Atomic end / post-atomic text:** atomic end and following text offset 0 share a wire — `resolvePaintPosFromFocus` paints the **text** owner. **Exception:** when blank-band substantive content abuts a probe (glued postfix chip), paint stays at atomic end so DOM stays off blank-band infrastructure (same gate as `resolveDomPointAtDocPos`). Click ingress consumes `paintPos` only — no second seam rewrite.
- **`layoutRowForFocus` / `layoutRowIndexForDocPos`:** canonical row lookup from focus doc pos via `resolvePaintContext` → `paintContextForDocPos(paintPos)`, else `rowIndexForWire(paintWire)`. When atom start was measured, missing atom offsets are stamped from that start sample only (never blank-probe wires; never storage line-start — soft-wrap can put the atom on a lower visual row). **Content→blank bracket:** unsampled wires before a blank-probe sample keep the preceding content sample’s row — do not interpolate onto the blank row (atom end often aliases the probe wire). Cross-row inter-atomic spacer text may still prefer measured text paint when it sits above the following atom.
- **`describeCaretContext(doc, focus, { root? })`:** delegates to `resolvePaintContext`; returns full `HandoffNoteCursorContext` for mention-boundary detail when `caretKind` is not `text`.
- **`paintContextForDocPos(pos)`:** primary layout paint index keyed by paint doc pos. **`paintContextForWire(wire)`** is a wire-export shim: `paintContextForDocPos(resolvePaintContextAtWire(doc, wire).paintPos)` when DOM layout has root (else sample-by-wire index). No raw-wire fallback after paint projection.
- **Wire remains export/mutation authority:** `docPosToWireOffset`, `getCursor()`, wire edits — unchanged. Same-wire alias seams: **doc pos for paint/row/caretKind; wire for export.**
- **Cross-row inter-atomic spacer is not soft-wrap continuation:** whitespace-only pre-atomic gap painted on row N with following atom on row N+1 is **not** `isWrapContinuationStartClickInRowAbove` / `viewportAliasesStaleWrapContinuation`. Click ingress uses `layoutRowForFocus`, not `rowIndexForWire(liveWire)`. Layout tags these gaps in `crossRowInterAtomicSpacers` so soft-wrap continuation promotion does not claim them.
- **Core insert at spacer text tail:** `appendInPreMentionText` with `preserveSeparator: true` keeps trailing space so focus stays text, not mention-start alias.
- **DOM boundary (read/write):** `setDocSelection` writes via `resolveDomPointAtDocPos` using `resolvePaintContext` paint pos. Passive strand read applies authority doc pos on same-wire alias seams (`resolveDomReadDocPos`). Viewport probe `caretKind` uses `resolvePaintContext`.

- **Rule 1 — click wins:** If a click resolves to a valid DOM text position on the editor, **accept it** as authority.
- **Rule 2 — repair scope:** Repair on `selectionchange` runs only when the click lands in an **invalid or unrepresentable** region (e.g. pill interior strand, selection outside root) — not when live wire reads as a blank probe but the DOM still resolved meaningful text on the intended row.
- **Rule 3 — no regress:** Repair must **never move the caret farther from the user’s click target** when a valid position already exists.
- **Rule 4 — text-node tail ownership:** The trailing edge of a substantive content text node (browser `offset === text.length` on that node) maps to **content row end** — the last character on that row — not the following wire `\n` or blank-band probe. Blank-band probe wires apply only when the browser places the selection in blank-band infrastructure (blank anchor, wire-break caret target, or explicit probe resolution from `resolveDomPointAtDocPos` at a probe wire). **Write paint:** content row end focuses the **last character** and paints at the browser text-node **tail** (insertion point after that character) — including sole-char and whitespace-only parts. The wire `\n` itself always paints via `domPointAfterWireBreak` (`<br data-handoff-wire-break>` / blank anchor / line-start) — never as a text-tail stand-in for content row end. **Sole/last char before `\n` affinity:** that wire is ambiguous between **visual start / deletion point** and **content row end**. Selection carries `focusAffinity`. **Delete = unit ahead; Backspace = unit behind** (general convention). Same-key behavior only for non-collapsed selection delete and when both keys nip the same blank-band unit. On the ambiguous wire: `before` = caret at the char's visual start (paint offset 0; insert at the char; Delete's unit ahead **is that char**); `after` = content row end (paint text-tail; insert after the char; Delete's unit ahead is the following `\n` / blank / join). Omitted affinity means **unspecified** on that wire — not a CRE claim. Insert/paint default to content-row-end; Delete does not invent blank collapse without an established `after` (treats the focused char as the unit ahead). Overlay reconcile must preserve affinity recovered from the native text-tail (or prior authority) on the same ambiguous wire. **Landings:** in-row Backspace/Delete stay at the deletion point (`before`); leftover whitespace-only residue after **atomic remove** (commit space) lands `before`; blank-fill / continued typing / row-chip CRE / atomic remove onto **substantive** content-row-end land `after` so the next Delete stays forward. **Insert landing:** when authority focuses a **non-probe** `\n` after substantive content, `resolveDomReadDocPos` keeps that `\n` when the browser strand reads as the preceding content text-tail — click-ingress last-char mapping must not collapse insert authority one wire behind.
- **Resolution order (overlay):**
  - **Strict live** — accept collapsed live when `isClickPosStrictlyRepresentable` (paint anchor hit, or live wire on the same layout row as the click, excluding mention-interior). Resolution: **`nativeSelection`**.
  - **Viewport pass** — when strict live misses: **`probeViewportCaretHit`** at click `(clientX, clientY)`; if the probe pos is **`isClickLiveRepresentable`** (including wrap-continuation past content extent via `isWrapContinuationStartClickInRowAbove`), take the **probed doc pos** (normalized) — resolution **`viewportCaretHit`**. Do not replace a representable probe with `docPosAtContentWire` at the same wire; alias seams can share a wire between text-tail and mention-boundary owners. Viewport wins over stale cross-row live when the probe finds a representable click-row hit. **Exception:** when live is **text** at the wrap continuation on the row below and the probe resolves the clicked row’s **content row end** alias (`viewportAliasesStaleWrapContinuation`), reject viewport — fallback keeps stale continuation live. Mention live at the continuation wire still accepts viewport sticky restore.
  - **Fallback** — when strict live and viewport pass both miss, accept browser live with **paint owner** for its wire — resolution **`nativeSelection`**. `layoutContentRowEndWire` / sticky column remain for **vertical arrow** stickiness only.
  - Log field **`resolution`** names the winning path (`nativeSelection`, `viewportCaretHit`).

Industry norm (VS Code, Google Docs, Notion, Slack, CodeMirror): **click location wins** unless the DOM cannot represent the requested position. “Content row end above band” is **Backspace/Delete policy** (structural cleared-row-end), not click repair.

## Backspace / Delete at blank-band probes

Editor-owned (`beforeInput` / keydown → normalize `selection.focus` via `resolvePaintContext` → `applyDocDelete` → `resolveHandoffNoteDeleteIntent`); same probe wires as arrow landing (`listEmbeddedBlankBandProbeWires`). Overlay does **not** invent a second delete-step kernel — intent stays in core; the paint-port only supplies disambiguated doc focus (and preserves non-collapsed ranges on `beforeInput`).

### Delete authority (principles)

- **Single authority:** `resolveHandoffNoteDeleteIntent` decides meaning from **doc position + direction + `focusAffinity`** before any splice. **Delete = forward (unit ahead); Backspace = backward (unit behind).** Both keys enter the same affinity gate (`resolveDirectionalUnitFocus`): on the ambiguous last content char before `\n`, `after` means Delete advances focus to the following `\n` (blank collapse / join) and Backspace's unit behind is that focused char; `before` / omit keep focus on the char (Delete nips it; Backspace uses generic unit-behind). Insert omit→append is a separate policy — not this helper. Affinity attach/preserve lives in core (`focusAffinityIfAmbiguousBreak`, `collapsedSelectionCarryingAffinity`, `collapsedSelectionReconcilingAffinity`, `normalizeSelection` drop when not char-before-break). Overlay reconcile and delete ingress call those helpers — DOM text-tail → `after` via `focusAffinityFromNativeDomPoint`; must not wipe via affinity-less `collapsedSelection` on the ambiguous wire. No cross-key flags (`chipBeforeBlankBand`, `pendingBlankBandDelete`, etc.) — prior edits affect **caret landing only**, not what the next key “means.”
- **Collapsed caret — one unit per key:** **Backspace** removes **one unit behind** (one character, one blank visual row, or one whole mention atom). **Delete** removes **one unit ahead** under the same rules. **Selection** deletes the highlight; both keys behave the same on a range.
- **Mentions are units:** a committed pill is one atom for delete intent. Backspace at mention **start** with a mention immediately left removes the **left** pill (including glued `@A@B`). Delete at mention **start** removes the **right** pill. Interior/backspace-end paths still use `resolveHandoffNoteMentionEdit` / `snapDeleteCaretWire` where documented below.
- **Paint vs intent:** the same wire offset can alias probe infrastructure and content-row end after a chip. **Intent** uses structural helpers with **focus doc position** when required (`embeddedBlankBandAtEmptyContentRowEnd`, `handoffNoteCaretAtClearedContentRowEndBeforeProbe`, `isEmbeddedBlankBandDeleteProbeWire`). **DOM paint:** `domPointAfterWireBreak` owns **every** break-wire paint with focus (cleared row end → `<br data-handoff-wire-break>`; delete-probe → blank-band anchor text; substantive non-probe `\n` → `<br>`). Rule 4 write for content row end uses the **last character** focus — do not remap the break wire itself to a text-node tail. Do not re-classify delete-probe in the text-split path.

### Probe classification (structural, not flags)

- **Delete-probe infrastructure** (`isEmbeddedBlankBandDeleteProbeWire`): caret on blank-band infrastructure — the blank visual row owns the unit. Backspace/Delete each remove **one blank-row `\n`** per keystroke (never the populated row above/below on that same stroke). Wire-only checks suffice for navigation onto a probe; **with focus**, interior band tail probes and EOF trailing-band tail probes stay delete infrastructure even when `focusWire === lineStart`.
- **Empty content row end** (`embeddedBlankBandAtEmptyContentRowEnd`): caret on the **cleared** substantive row gate before a probe (row above probe is empty **and** focus matches semantic row end / line-start gate via `handoffNoteCaretAtClearedContentRowEndBeforeProbe`). **Not** interior band tail (last probe in a multi-probe band with substantive tail below) and **not** EOF trailing-band tail (last probe with no substantive row below the band). After chip, the next backspace/delete on that gate collapses blank per empty-row-end paths — not “armed” by a consumed flag. Clearing the last unit on a content row never collapses the blank on the same keystroke.
- **Cleared-row misfire guards:** `isBlankBandInteriorTailProbe` and `isBlankBandEofTailProbe` prevent `focusWire === lineStart` from classifying band-interior or EOF-tail probes as cleared content row end.

### Content row chip and landing

- **Content row chip:** backspace or delete on trailing row text immediately before a probe removes characters normally (including the last character on the row). Deleting the last character does **not** promote the caret into blank-band delete-probe paint; landing uses `docPosAfterPartialContentRowChipBeforeProbe` / `docPosAfterEmptiedContentRowChipBeforeProbe` / `embeddedBlankBandContentRowEndBeforeProbe` so the caret rests on **cleared content row end** or mention alias, not zwsp infrastructure.
- When a partial chip leaves substantive text on a **sole-char sandwiched** row, caret **doc position** lands on **char wire** (visual start), not probe-wire paint — wire index alone is ambiguous (`docPosAfterPartialContentRowChipBeforeProbe`).
- When substantive content abuts a probe (`embeddedBlankBandSubstantiveContentAbutsProbe`), chip and collapse landing use **`docPosAtEmbeddedBlankBandProbeAliasLanding`** / **`docPosAfterEmptiedContentRowChipBeforeProbe`** — authority on **mention-node end** or cleared content-row end, not blank-band zwsp infrastructure. This covers **spacer chips** and **glued postfix** substantive chips (mention abuts probe with no spacer).
- **Collapse selection landing** (`blankBandSelectionFocus`): after blank-band **collapse** moves, caret rests on the **probe wire** by default. When prior focus already owned the atom/CRE alias at that probe (atom abutting the probe — including delete forward through `resolveDeleteForwardFromAtomicAbuttingProbe`), landing stays on that alias — not raw probe infrastructure. Derived from prior focus in intent; no landing-meaning flag on the move.
- **Delete intent order:** mention interior abutting probe (backspace/remove paths); Backspace + affinity `after` on content-char-before-break → unit behind is that char (row chip when next wire is a blank-band probe, else ordinary splice); mention **node** end backspace → atomic mention remove; mention **node** end at probe alias + Delete → blank collapse look-right via forward path (embedded blank-band delete or empty-row-end fallback); Delete on spacer-before-probe / content-row-end → row chip (unit ahead); Backspace at visual start (`before` / omit) on that same char → unit behind (prior char or BOF noop) — never chip the focused char ahead; text-node caret on probe wire without content-row alias → blank collapse per band rules below.

### Branch taxonomy (implementation labels)

Logged on delete moves; drives `blankBandSelectionFocus` landing buckets:

- **`row-chip-before-probe`** — remove trailing row text when caret is on the **content row** immediately before a blank-band probe (not when caret is on the probe itself).
- **`step-to-content-row-end`** — retired for delete-probe caret (blank row owns the unit: collapse the blank, then land). Kept only as a legacy debug label if predicted.
- **`backspace-collapse-blank`** — backspace on blank-band delete infrastructure removes one blank-row `\n`; land **upward** (blank probe above if any, else content row end above; leading-only → next row visual start below).
- **`delete-collapse-blank-mid-band`** / **`delete-collapse-blank-at-edge`** — delete on blank-band infrastructure; mid-band lands on next probe below, band edge lands on lower substantive **visual start** (trailing last blank → no-op).
- **`backspace-line-start-collapse`** — Backspace only: line-start storage `\n` (not a blank-band probe) before lower substantive content when **every** segment above is empty (leading blanks). Does not apply when any substantive segment remains above. Delete on that same `\n` is ordinary forward splice (land at lower visual start) — not this branch.
- **`backspace-line-break-join`** / **`delete-line-break-join`** — single substantive `\n` between two populated rows (not a blank-band probe): merge rows; caret at join point.

### Row-chip authority (doc position)

Row chip on **Delete** when the caret is on the content char immediately before a blank-band probe (including spacer-before-probe / sole-char). Row chip on **Backspace** only when affinity is `after` on that char (unit behind) or when the caret is on the probe with a content-row alias (chip the prior char). Visual-start Backspace (`before` / omit) never uses spacer-before-probe or CRE-at-focus to chip the focused char ahead — it nibbles the unit behind or noops at BOF. **≤2-char same text-node rows** at visual start: interior backspace nibble (char behind caret). Caret on multi-char blank-band probe infrastructure without alias: collapse, not chip.

### Directional nibbling (Backspace vs Delete)

- **In-row text (standard editor):** backspace removes the unit **behind** the caret; delete removes the unit **ahead**. The caret **stays at the deletion point** — no post-edit jump. When that point is a sole/last content char before `\n` (including leftover mention commit space), authority keeps `focusAffinity: before` so the next insert and paint stay at that visual start — not content-row-end text-tail. Example (caret landing only): visual row 0 `he`, rows 1–2 blank; caret after `h` on row 0 → backspace removes `h`, row 0 is `e`, caret stays **before** `e` — not after `e`. At **visual start** of a populated row, backspace does **not** nip that row’s text (nothing behind the caret on that row); use **delete** forward or move the caret to **content row end** to remove text ahead on the same row. Follow-up (blank above, same row still `e`): visual row 0 blank, row 1 `e`, caret before `e` on row 1 → backspace nips the **blank on row 0**, not `e`. At **content row end** of a populated row, delete does **not** nip further on that row without moving.
- **Progressive trashing landings (blanks and band edges only):** when the next key must keep trashing through **blank infrastructure** or reach populated text on the **adjacent** row, land so the following keystroke works in that direction — backspace → **blank above** or **content row end** on the populated row above (affinity `after` on that last content char before the residual `\n` — whether the `\n` is still a blank-band probe or has become a substantive join after the last blank was removed — so the next Backspace removes it as unit behind); delete → **next blank below** or **visual start** on the populated row below. Applies after blank-band collapse and blank-band exhaustion — **not** after an ordinary in-text backspace/delete on a populated row (in-row nibble keeps `before` / deletion-point for insert). Every blank-band delete move carries `landingIntent` from its producer (`collapseBlankBandBackspaceLanding` for upward CRE); delete-intent applies it and does not re-derive affinity from residual probe topology.
- On **blank** rows, each key nips **that blank** (one blank visual row per keystroke) in its direction — not populated text on another row. Backspace does not chip the row above while caret remains on the blank; Delete does not chip the row below’s content until landed on that content row.
- **Inter-mention gap:** only a **whitespace-only** text node between two pills (no embedded newline, no substantive chars). Backspace/delete chips or merges that separator per direction; after a merge that glues adjacent mentions, caret lands via `caretAfterInterMentionGapMerge` so the **next** key’s left/right unit matches user intent (row-prefix end when substantive text precedes the left pill, else right-pill start). **Substantive** text between mentions is ordinary text: backspace at its visual start removes the **left** mention atom (standard unit-left), not the first character ahead.
- **Blank-band collapse (Backspace):** each backspace on blank-band delete infrastructure removes one blank-row `\n`. Land **upward**: remaining blank probe above if any; else **content row end above** when substantive content sits above (trailing or sandwiched) — including after the **last** blank is gone and the residual `\n` is an ordinary substantive join; when **no** substantive row sits above (leading blanks), land at the **visual start of the next row below** and keep nipping blanks until populated content start (then stop — nothing behind on that row; do **not** mark that lower start as content-row-end even if it is a sole char before `\n`). Do not leave the caret on a blank below after nipping when content sits above.
- **Line-start collapse (Backspace):** a `\n` immediately before lower substantive content (line-start storage, not a blank-band probe) collapses on backspace when every segment above it in the wire is empty — one blank-row nip; land at the first substantive row **visual start** (stop nipping if populated; continue blank nipping only while rows below remain blank). Ordinary Backspace cannot remove a unit behind the caret when that `\n` sits at wire 0 (BOF); Delete removes the same `\n` as the unit ahead without this branch.
- **Substantive line-break join:** a single `\n` with **populated rows on both sides** (normal `line1\nline2` storage — not a blank-band probe) merges on **backspace at the lower row visual start** or **delete on the break wire**; caret lands at the join point (end of upper row text). Distinct from blank-band collapse and from in-row nibble on the upper row.
- **Blank-band collapse (Delete):** mirror **downward** — each delete on blank-band delete infrastructure removes one blank-row `\n`. **Within a band**, land on the **next blank probe below** and repeat. When **no substantive row sits below** (trailing blanks only), delete **nips blank rows themselves** downward — one per keystroke — until the band edge or a single trailing row; delete never jumps to a row above. When that was the **last blank before populated content below** (including **sandwiched** blanks), land on the **lower substantive row visual start** so repeated delete nips that populated row from the front. Delete never lands at content row end above.
- **Delete at probe, substantive row below (last blank before content):** lower content row **visual start** (same as delete collapse exhaustion below).
- **Band edge no-op:** backspace/delete only no-op when there is nothing to merge in that direction **and** no substantive row to land on (e.g. doc end with trailing blanks only).

## Left / Right — horizontal only

- Move one logical step along the wire on the **current line** (same primitive as vertical boundary bleed).
- **Paint seam authority:** overlay `resolvePaintHorizontalArrowMove` owns horizontal landing via doc-primary stepping — `resolvePaintContext` → `resolveHorizontalDocStep(focusPos, direction)` → **selection lands on `resolvePaintContext(landed).paintPos`** (normalize). Text steps intra-offset ±1 when inside a text node. Atomic nodes (any non-text node today) use `describeHandoffNoteCursorContext` at focus wire: interior left → atomic offset 0; interior right → position after atom; boundary start right → atomic end; boundary end right → position after atom; boundary start left → preceding text char (not same-wire tail alias); boundary end left at aliased post-atomic text offset 0 → atomic offset 0. **Alias landing:** when step focus is atomic end and paint owns post-atomic text at the same wire, the returned selection is that text owner — so writeSelection/DOM stay aligned and the next Right advances into the spacer (no `keepAuthority` mention-over-text dead press). **Soft-wrap spacer vs click:** wrap-tail spacer and continuation are **separate horizontal stops**. Right from mention start/end lands post-text paint (spacer when that is the wrap prefix); Right from that spacer enters continuation via normal text step. Click ingress may land continuation directly — click owns that; horizontal must **not** promote spacer→continuation in the same press (that skips mention-end/spacer). Same-row sandwich spacers stay a real stop. Left from continuation still lands the spacer. Wire import at alias seams uses `resolvePaintContextAtWire(...).focusPos` so focus matches canonical owner, not paint pos alone.
- **Pill atomic (horizontal):** step over a pill as one token; never land inside pill interior text via Left/Right. Right from text immediately before an atom crosses the atom to post-text paint (no mention-start micro-stop / same-wire flip). Mention **start** remains a landable caret when already focused there (e.g. after Left onto start); Right from start still steps to atomic end → paint post-text.
- **Mention-interior authority (delete / blank-band step):** `row-chip-before-probe` at content-row end before a probe lands on semantic content row end (`embeddedBlankBandContentRowEndBeforeProbe`), not raw `probe − 1` when that wire is mention-interior. After blank collapse, Backspace landing on content row end uses the same semantic end helper. Canonical `normalizeDocPos` **preserves** interior only when no disambiguation hint is supplied on unrelated paths. Ingress repair restores editor authority when DOM drifts to a blank-probe alias at the same wire offset. After a post-mention **whitespace chip**, when substantive content abuts the probe (`embeddedBlankBandSubstantiveContentAbutsProbe`), authority rests on mention-end / content row end (`docPosAtEmbeddedBlankBandProbeAliasLanding`) — not blank-band zwsp paint at the alias wire.
- **Adjacent mentions on one line:** step mention-to-mention here, not with Up/Down (except boundary bleed above).
- **At doc start + Left** or **doc end + Right:** no-op when unhandled (stay at start/end).

## Shared

- **Delete caret policy:** every `applyDocDelete` result passes through `snapDeleteCaretWire` — default interior snap is **directional** (backspace → atom-end, delete → atom-start). After an **atomic remove**, **`resolveHandoffNoteDeleteIntent`** lands the final caret: substantive CRE gets `after`, leftover commit-space residue stays `before`. Snap is directional **interior** escape only (backspace → atom-end, delete → atom-start) — not a second landing author. Intent is the single delete authority (doc position + direction + `focusAffinity` before any splice; no cross-key context flags). **Content row end above a probe** resolves semantically via `embeddedBlankBandContentRowEndBeforeProbe`: when physical `probe − 1` falls inside an atom, landing is **atom-end** on that node, not interior. When the row above is **atom-only** (no prefix text on the line), backspace at the probe collapses blank infrastructure (blank row owns the unit). Post-atom **commit spacer** is its own text unit when the caret is on it; forward atomic remove removes the atom only; the next Delete owns that spacer (one unit per key).
- **DOM boundary mapping:** `domPointToDocPos` applies click ingress Rule 4 at ingress — text-node tails belong to content row end; blank-band probes come only from blank infrastructure DOM. **Break-wire paint:** `domPointAfterWireBreak` (via `resolveDomPointAtDocPos`) is the sole owner for focus on a `\n` — cleared content row end → wire-break `<br>`; delete-probe → blank-band anchor; substantive non-probe line break → `<br>`. Content row end with substantive text still on the row focuses the **last character** (Rule 4 write), not the following `\n`. **`resolvePaintDocPos`** applies cross-row sandwich spacer alias for DOM paint only. **`isEmbeddedBlankBandDeleteProbeWire(doc, wire, focus)`** requires focus when the wire aliases cleared row end — wire-only checks misclassify spacer-chip landing. Delete policy uses the blank-band collapse family in **Backspace / Delete at blank-band probes**.
- **Mention boundary DOM paint:** `resolveDomPointAtDocPos` places committed-pill **start** and **end** boundary carets outside the pill element; only **interior** offsets paint inside pill text. **Row-start atom** (wire-break immediately before an atomic node, no pre-atom text on that row): render emits a non-wire ZWSP **line-start anchor** after that break (`lineStartBeforeAtomic` / `isAtomicNode`); **atom-start** paint targets the anchor text via `paintOutsideAtomicStart` — not the `<br>` and not `(root, atomChildIndex)` (both yield empty collapsed-selection client rects). **Break-wire focus** on that same preceding `\n` still paints the `<br>` (`domPointAfterWireBreak`) so layout geom and live/authority parity stay on the break. Read-back from the anchor maps to atom-start / text-gate end (same wire). **Mid-row spacer tails** (e.g. `" "` before a same-row sandwich atom at `text.length`) keep text-node paint — do not rewrite them to atom exterior. **Rule 4 write:** content row end (focus on last char) paints the text-node **tail** (insertion point after that character) for multi-char, sole-char, and leftover whitespace alike. The following `\n` paints via break path. **Blank-fill insert:** type into a blank probe inserts after the probe; caret rests on the **last inserted char** (content row end). Further typing inserts after that char (before the following `\n`) then snaps back to the new last char — never leave the caret on the following break for paint. Collapse moves land on probe wire by default; when prior focus already owned the atom/CRE alias at that probe, landing stays on that alias (spacer or glued postfix chip paints atom-end boundary, not blank-band anchor).
- **Mentions:** vertical crosses rows; horizontal crosses tokens on a row.
- **Atom extensibility:** adding a node type requires (a) core cursor context or generic atomic boundary classification, (b) if a new alias seam appears, one rule in `resolveCanonicalFocusAtWire`, (c) horizontal step uses existing atomic branches via `isAtomicNode` + caret context — no new horizontal shim per node type.
- **Atom-seam starvation (scale rule):** seam helpers for alias / paint / row / caret-at-boundary classification are **atom-generic** — `isAtomicNode` + `nodeTokenLength` from `@caliper/core`, `resolvePaintContext` / `resolveCanonicalFocusAtWire`, layout acquire stamp (`stampAtomicInteriorPaintKeys`). **Mention** vocabulary stays on product facts only (pill DOM, cursor-context kinds, inter-mention gap, `resolveHandoffNoteMentionEdit`). Do **not** add new `*Mention*Wire*` seam helpers for paint/row/alias; wire remains export/mutation transport. Import `isAtomicNode` from `@caliper/core` — do not re-export through overlay modules. Delete/selection boundary gates prefer doc-pos atomic predicates + paint focus over wire-only `describeHandoffNoteCursorContext` re-classify when focus is already known.
- **Tests:** integration and unit tests assert **contract behavior**, not implementation branches. A failing test means the code or the oracle is wrong — **never weaken the contract** to green a patch. Wrong tests get fixed or removed; symptom-specific landing rules are not added to satisfy a test.
- **Logging (debug):** direction, `fromWire`, `toWire`, `branch`, `lineIndex` delta.

## Pill click selection (editor)

- **Click pill:** select that **doc node instance** only (`selectedMentionNodeIndex`); native caret cleared; tray may still set `highlightedAgentId` by agent id.
- **Highlight in note:** by **node index**, not agent id — duplicate `@` pills do not all light up.
- **First arrow after select:** vertical → **row start** of that pill’s wire line; horizontal → **pill end**; then normal caret navigation.
- **Clear selection:** text mousedown, typing, doc mutation, `@` popover open, or arrow exit.
- **Popover open:** list arrows stay on popover; editor pill exit is suppressed and pill selection is cleared on popover input.
